# Education and docs header patterns: what is outdated, harmful, or actually shipped

Scope note for the report writer: this file records evidence only. It does not propose a Chaduvuko header. Live checks were made on 9 October 2026. Several fetches returned reader-style text and dropped site chrome, so a missing control in an extract is not evidence that the control was removed. Each bullet is tagged **Observed** (a page fetched or a changelog/design-system page that describes a shipped UI), **Sourced opinion** (a named design-system or research claim), or left to Inferences.

## Which once-standard header pieces have top learning or docs sites dropped?

### Takeaway

There is no 2023–2026 primary source showing Khan Academy, Duolingo, MDN, Stripe, GitHub, or Vercel jointly deleting announcement bars, login buttons, social icons, taglines, language switchers, theme toggles, header breadcrumbs, lesson counts, or “Ask AI.” What serious design systems have actually rejected is a header that is also a sitemap: full topic menus inside a task, full-path breadcrumbs in the app bar, and chrome stacked on chrome. Several of the “old” pieces are still on live pages in October 2026.

### Cited Findings

- **Announcement bars are not gone.** On 9 October 2026 the roadmap.sh frontend roadmap still opened with a partner strip (“Get the latest Frontend news from our sister site”) above the roadmap title, plus a visible `⌘ K` control. **Observed.** — [roadmap.sh frontend](https://roadmap.sh/frontend)
- **GOV.UK kept a service-wide message strip, and specified where it goes.** The phase banner sits directly under Service navigation (or under the GOV.UK header if Service navigation is absent), on every page of a service, because users should read it as a service-level message rather than page content. This is a status banner, not a marketing announcement. **Sourced opinion / specified pattern.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/)
- **Top-of-page strips that look like ads are ignored, and stacked strips eat the phone.** NN/g’s 2018 eyetracking write-up (still the canonical primary study; no newer NN/g replacement was found) says people ignore content that resembles ads, including content at the top of the page, and that legitimate content in ad-like spots is ignored too. A separate 2021 NN/g article says a sticky header plus a second sticky bar can crush the content-to-chrome ratio on a phone (their Lollar Pickups example was about 2:1). **Sourced opinion.** — [Banner Blindness Revisited](https://www.nngroup.com/articles/banner-blindness-old-and-new-findings/); [Sticky Headers: 5 Ways to Make Them Better](https://www.nngroup.com/articles/sticky-headers/)
- **Login is still normal when the product is an account, and is questioned when it is not a repeated task.** GitHub’s product UI still documents account-scoped commands (new repository, switch theme) inside a signed-in command palette. NN/g’s sticky-header guidance asks designers to justify a login control in a persistent header: only if users are likely to log in from any page in a session. No 2023–2026 changelog was found in which an education library removed “Log in” from every page. **Sourced opinion, plus a gap on education-site removals.** — [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette); [Sticky Headers](https://www.nngroup.com/articles/sticky-headers/)
- **Social icons were not found in the global headers that did render.** roadmap.sh places LinkedIn, YouTube, X, and Bluesky links in the footer, not in the top bar of the frontend roadmap. Primer says the app footer holds useful links and legal information and stays below the fold so the page can focus on main content; rich interactive pages may omit the footer. No design-system page found in this pass bans header social icons by name. **Observed for roadmap.sh; sourced opinion for Primer footer role.** — [roadmap.sh frontend](https://roadmap.sh/frontend); [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **Taglines still appear on catalog pages, not as a required header part.** The roadmap.sh frontend page’s H1 is followed by “Step by step guide to becoming a modern frontend developer in 2026.” Primer’s page header region may include a title plus an optional summary. That is a page summary, not a global tagline in the app bar. **Observed; sourced opinion.** — [roadmap.sh frontend](https://roadmap.sh/frontend); [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **Language switchers were not dropped; they were given a slot.** GOV.UK says: if the whole service is offered in more than one language, put the language navigation component in Service navigation. The GOV.UK header itself is only for the logo and GOV.UK-wide tools. A Stripe docs search extract from this pass still showed “English (United States)” in the docs chrome; the fetched Stripe docs markdown home did not include that chrome, so the locale control was not re-verified in the full page body. **Sourced opinion; Stripe locale only partially observed.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/); [Stripe docs home](https://docs.stripe.com)
- **Theme controls moved for some products and stayed visible for others.** GitHub documents “Switch theme to &lt;theme name&gt;” as a global command-palette command, so theme change does not require a dedicated header icon. The same docs page still says the palette can switch themes “with a few keystrokes.” Next.js docs, fetched the same day, still expose “Select a display theme” in the same top region as search. **Observed.** — [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette); [Next.js docs](https://nextjs.org/docs)
- **Full-path breadcrumbs do not belong in the app header, according to two design systems.** GOV.UK: if you use breadcrumbs, place them just before `<main`, so “Skip to main content” skips navigation and breadcrumbs together. Primer: the context region (for example `:owner / :repository`) “is not a full-path breadcrumb”; do not append the current section (“Issues”, “Projects”) there, because local navigation already shows it. W3C’s breadcrumb pattern says a trail is “often placed horizontally before a page's main content,” inside its own navigation landmark, with `aria-current="page"` on the current page. **Sourced opinion.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/); [Primer layout](https://primer.style/product/getting-started/foundations/layout/); [W3C breadcrumb pattern](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/)
- **GOV.UK removed service name and service links from the header component itself.** The pattern and Service navigation component shipped in August 2024. By February 2026, GOV.UK Frontend v6.0.0 removed the parameters for setting service name and navigation on the GOV.UK header. The header is logo plus GOV.UK-wide tools; service name and service links live in Service navigation. **Observed in the design-system changelog.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/); [GOV.UK header component](https://design-system.service.gov.uk/components/header/)
- **“Ask AI” has not been dropped on flagship docs.** Next.js docs on 9 October 2026 showed “Search… ⌘K” and “Ask AI” together in the top region (the label appeared twice in the extract, consistent with a duplicated desktop/mobile control, not with removal). Vercel’s February 2026 dashboard-navigation changelog page also exposes “Ask AI” in its page chrome. No primary post was found that calls the button harmful or that records a docs site removing it. **Observed.** — [Next.js docs](https://nextjs.org/docs); [Vercel dashboard navigation redesign](https://vercel.com/changelog/dashboard-navigation-redesign-rollout)
- **Lesson counts were not found inside menus.** The Odin Project paths index shows “7 Courses” and “8 Courses” on path cards in the page body. The lesson URL fetched the same day returned almost no body (title plus a support pitch only), so its header and curriculum menu could not be read. **Observed on the paths index only.** — [The Odin Project paths](https://www.theodinproject.com/paths); [How Does the Web Work?](https://www.theodinproject.com/lessons/foundations-how-does-the-web-work)
- **A header that lists every section is explicitly rejected.** GOV.UK: “Navigation is not a site map and does not need to list every part of your service.” Links “must go to the most important top-level sections.” Once a user is inside a service, do not add the GOV.UK topic menu; exploration belongs on the homepage and mainstream guidance, not in the service. Red Hat’s primary-navigation guidelines: “Do not overload the Primary navigation with tons of primary menus or other elements.” **Sourced opinion.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/); [Red Hat primary navigation guidelines](https://github.com/RedHat-UX/red-hat-design-system/blob/main/elements/rh-navigation-primary/docs/20-guidelines.md)

### Inferences

- The pieces that look “outdated” in 2026 are not a banned component list. They fail when they occupy the global bar on a long reading page: a marketing announcement, a social row, a tagline, a lesson-count menu, and a full breadcrumb are five different jobs piled into one strip. Design systems that rewrote navigation in 2024–2026 (GOV.UK, Primer, GitLab, Vercel’s dashboard) split those jobs instead of deleting search, account, or language.
- “Ask AI” and theme controls are current docs-header furniture on developer sites, not a retracted 2023 trend. The cost is width and target size, which is a failure mode (see the last section), not evidence of abandonment.
- A login control on every page is weakly justified for an optional-account library. That conclusion is NN/g’s 2021 test (“will users log in from any page?”), not a published removal by Khan Academy or Duolingo.

### Gaps

- No public 2023–2026 post was found from Stripe, Khan Academy, Duolingo, MDN, or The Odin Project saying they removed announcement bars, social icons, taglines, language switchers, theme toggles, header breadcrumbs, or lesson counts.
- Khan Academy’s marketing home extract showed teacher “Sign up” and “Start for free” in page sections, not a parsed global header, so login placement on khanacademy.org was not verified. — [Khan Academy home](https://www.khanacademy.org/)
- MDN’s “Your first website” extract contained the article only (last modified 23 June 2025). Sidebar and header chrome were stripped, so MDN’s live header could not be inventoried from this fetch. The writing guide still requires sidebars. — [Your first website](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website); [MDN sidebars](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Page_structures/Sidebars)
- Stripe docs markdown and the Material Design 3 navigation-bar pages returned no usable chrome (`m3.material.io` returned “No content found”). Material’s numeric rules for bar capacity were not re-verified.
- Duolingo lesson chrome is behind a session. No 2023–2026 Duolingo design post about the lesson header was found. The official path redesign post is from 6 May 2022, outside the requested window, and is cited only where the behavior is still the public description of the product. — [New Duolingo home screen](https://blog.duolingo.com/new-duolingo-home-screen-design/)

## Which newer patterns are real and widely shipped by serious products?

### Takeaway

Command palettes and a local, collapsible sidebar are widely shipped on developer docs and on GitHub itself. A hideable sidebar and a mobile bottom bar are shipped for app dashboards (Vercel, GitLab, Apple). A lesson-specific “resume” control is documented for Duolingo’s path, not as a cross-site header standard. Reading-progress bars, a study mode that replaces navigation, and a fixed bottom prev/next lesson bar were not verified on the education sites checked.

### Cited Findings

- **Command palette, GitHub, still shipping after a 2025 attempt to retire it.** GitHub Docs, fetched 9 October 2026: the palette opens with Ctrl/Command+K from anywhere, scopes suggestions to the current org or repository, searches issues, files, users, and projects, and runs commands including theme switch. It is in public preview and off by default until enabled in feature preview. On 16 July 2025 GitHub paused a planned deprecation: “Your feedback highlighted how integral this feature is to many developers’ workflows,” including value “beyond what our usage metrics captured.” **Observed.** — [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette); [Pausing Command Palette deprecation](https://github.blog/changelog/2025-07-15-upcoming-deprecation-of-github-command-palette-feature-preview/)
- **Command palette, docs sites, October 2026.** Next.js docs tell readers to use the sidebar or search with Ctrl+K / Cmd+K, and the top region shows “Search… ⌘K”. Tailwind’s installation doc shows “⌘K” and “Ctrl K” beside Docs, Play, Blog, Showcase, Partners, and Plus. roadmap.sh shows “⌘ K” on the frontend roadmap. **Observed.** — [Next.js docs](https://nextjs.org/docs); [Tailwind installation](https://tailwindcss.com/docs/installation/using-vite); [roadmap.sh frontend](https://roadmap.sh/frontend)
- **Command menu, Vercel, documented for dashboard and docs, with a dead URL.** An indexed Vercel page last updated 24 September 2025 describes a Command Menu on ⌘K / Ctrl+K for the dashboard (jump to a project or team; shortcuts include theme toggle) and, on the documentation site, search across Vercel properties from the same shortcut. Fetching `https://vercel.com/docs/dashboard-features/command-menu` on 9 October 2026 returned a 404, so the current canonical URL was not confirmed. **Sourced from the indexed doc; live URL unverified.** — [Indexed command-menu doc](https://zeit.co/docs/dashboard-features/command-menu); [404 on the docs path checked](https://vercel.com/docs/dashboard-features/command-menu)
- **Vercel’s 2026 dashboard nav is a hideable sidebar plus a phone bottom bar, not a taller header.** As of 26 February 2026 the default dashboard navigation is: horizontal tabs moved into a resizable sidebar that can be hidden; the same tab set at team and project level; items ordered by the most common workflows; projects acting as filters; “floating bottom bar optimized for one-handed use” on mobile. **Observed changelog.** — [New dashboard redesign is now the default](https://vercel.com/changelog/dashboard-navigation-redesign-rollout)
- **Local sidebar is the docs/article pattern, with its own scroll and a collapse control.** MDN’s writing guide (page updated 26 January 2026) says all MDN pages should have sidebars, defined in YAML and attached by front matter; a section title often links to that section’s landing page. GitHub Docs on the command-palette article expose “Collapse sidebar”, “Expand sidebar”, “In this article”, and skip links. Next.js docs say to use the sidebar, put an App Router / Pages Router switch at the top of that sidebar, and show “On this page”. Starlight’s getting-started page points readers at a sidebar-navigation guide and says “see the guides in the sidebar.” Primer split pages give the side pane its own scroll so a long list does not move the open document; the pane is flush left, not right, so its scrollbar does not fight the page scrollbar. **Observed and sourced opinion.** — [MDN sidebars](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Page_structures/Sidebars); [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette); [Next.js docs](https://nextjs.org/docs); [Starlight getting started](https://starlight.astro.build/getting-started/); [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **GitLab’s sidebar is contextual, optional, and hidden by default under 1200px.** Pajamas (page updated 15 July 2026): the header area stays stable while the sidebar body changes with context. The sidebar is omitted when navigation is not useful (minimal page layout). Users can hide it to focus on the body; the preference is stored. At 1199px and below it is hidden until opened as an overlay. Extra-large (1200px and up) shows it by default. **Sourced opinion from the design system.** — [GitLab navigation sidebar](https://design.gitlab.com/patterns/navigation-sidebar)
- **Do not dump the track list above the lesson on a phone.** Primer, narrow range is under 768px and is a single column. “Avoid stacking a pane on top of the main content area if the pane has a lot of links. It will push the main content down and force the user to scroll to get to the content.” Preferred adaptations: split list and detail into separate pages with a parent link, or open auxiliary panes as a bottom sheet. Primer’s `xsmall` breakpoint is 320px. **Sourced opinion.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **Apple: bottom tabs are for top-level areas; they stay visible; the top bar is for the current place.** Tab bars navigate sections and are not for actions that apply to the current view (use a toolbar for those). Hiding the tab bar makes people forget where they are; the exception is a temporary modal. iOS tab bars sit at the bottom. Toolbars should not be overcrowded. Change logs on these pages run through December 2025 and June 2026. The full toolbars page did not return a body in fetch; the quotations come from the indexed Human Interface Guidelines text. **Sourced opinion.** — [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars); [Toolbars / navigation bars](https://developer.apple.com/design/human-interface-guidelines/navigation-bars); [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- **“Back to where I was” is a real Duolingo path control, and it is not in the header.** Duolingo’s May 2022 home-screen article: the path is a long scroll; if you leave your current node, a floating arrow at the bottom right jumps back. Unit headers carry the topic labels that used to sit on each circle. This is the company’s own description. It was not re-checked inside a logged-in lesson in 2026. **Sourced opinion, older than the 2023 window.** — [New Duolingo home screen](https://blog.duolingo.com/new-duolingo-home-screen-design/)
- **Khan Academy says navigation and search improved in the 2026 reimagined product, and names a learning queue, not a header resume button.** Help Center article updated about June 2026 (USA rollout late June 2026): teacher and student “Site navigation” marked Improved; “Searching for content” Improved; student “Learning queue” Added. Discussions, avatars, and energy points were removed. No sentence describes the header, a continue button, or a lesson chrome. **Observed product note, low detail.** — [Khan Academy reimagined experience for administrators](https://support.khanacademy.org/hc/en-us/articles/46056304557837-What-do-administrators-need-to-know-about-the-Khan-Academy-reimagined-experience)
- **GOV.UK already recorded a failed “navigation header” on a guided learning-like journey.** Step-by-step navigation (a sequenced journey shown as a right-hand sidebar on content pages, or as its own page) has this known issue: “Users rarely use the step by step navigation header, which might suggest the purpose of it is not clear to them.” Users also get frustrated looping between step-by-steps. **Sourced opinion from research notes in the design system.** — [Step by step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/)
- **Stripe’s public design constraint on an app header is “a few” actions.** Stripe Apps design docs: the header houses the app name, the view name, an external link, and a few top-level actions. Custom styling is limited so contrast and platform consistency hold. Dashboard search is a primary wayfinding tool for payments, customers, invoices, and similar objects, with immediate top results. This is dashboard/app chrome, not stripe.com marketing. **Sourced opinion.** — [Design your app](https://docs.stripe.com/stripe-apps/design); [Perform searches in the Dashboard](https://docs.stripe.com/dashboard/search)

### Inferences

- For a long written lesson, the pattern that is both specified and visible in 2026 is: a short global bar (identity, search or command palette, one or two utilities) plus a section sidebar that can collapse or become another view on a narrow screen, plus an in-page “on this page” list. That combination is what Next.js, GitHub Docs, MDN’s writing rules, Primer, and GitLab describe. It is not a header that contains the track.
- “Study mode that replaces nav” is easy to over-claim. The shipped behavior is closer to “hide or collapse the section nav so the document can use the width” (GitLab, Primer, Vercel’s hideable sidebar). Apple’s opposite rule, “do not hide the top-level tab bar,” applies to app sections, not to a document outline. Those are different layers.
- A bottom bar on mobile is real for switching top-level areas (Apple, Vercel dashboard). It was not shown here as the prev/next control for a written lesson. Treating dashboard bottom nav and a lesson pager as the same pattern is not supported by these sources.
- Reading progress was not established. Ebook-reader footers (position in the chapter) and Microsoft Teams “Reading Progress” (a fluency assignment) are different products and were not used as evidence.

### Gaps

- No live lesson player was successfully read for Khan Academy, Duolingo, Coursera, Exercism, or The Odin Project. The Odin lesson fetch returned 12 lines and no curriculum UI. Resume, reading progress, study mode, and bottom lesson controls on those products are unverified.
- A portfolio case study that puts a “Resume” button in a Khan Academy tab bar is an individual’s concept, not a Khan Academy release. It is not evidence. — [Scott Liang, Khan Academy redesign](https://www.scottliang.com/work/khan-academy-redesign)
- A January 2026 LinkedIn post about a sticky bottom sheet on a Duolingo lesson is a personal redesign exercise, not a Duolingo changelog. — [LinkedIn post](https://www.linkedin.com/posts/jiyaezekiel_uiux-productdesign-duolingo-activity-7419317137959370752-XTGT)
- Whether Vercel’s documentation command menu still matches the September 2025 write-up is unverified because the docs URL 404’d.
- Starlight’s own sidebar guide was not fetched; only the getting-started page’s references to it were.

## What do designers at Stripe, Vercel, GitHub, Khan Academy, Duolingo, or similar say in public about navigation simplicity?

### Takeaway

The clearest 2023–2026 primary statements are from GitHub Primer, GOV.UK, GitLab, Vercel’s changelog, and Apple’s HIG: keep the page focused, do not make navigation a map of everything, let people hide section chrome, and do not overcrowd the bar. Stripe, Khan Academy, and Duolingo do not have a matching public nav essay in the sources found. Duolingo’s on-record structural choice is the 2022 guided path, not a 2024 header manifesto.

### Cited Findings

- **GitHub Primer, layout foundations (live design-system page).** “A page should enable the person to focus on the content. We should respect the user’s attention, and provide an experience that is clean, calm, and uncluttered.” “App header is never fixed to the top of the viewport. It scrolls with the rest of the page.” Context region is not a full-path breadcrumb. Do not put custom buttons or dropdowns in that region. Do not stack a long link pane above the content on a narrow viewport. Pages must adapt to smaller screens without losing functionality. **Sourced opinion.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **GOV.UK Design System, August 2024 pattern, still the current guidance, with 2026 component edits.** “Simplify the user journey as much as possible first. This might remove the need for users to navigate around your service.” If the service is a clear end-to-end journey, do not use navigation links; use a task list. Navigation links are for services people repeat, that have multiple tasks and no single order. “Navigation is not a site map.” Do not show the GOV.UK topic menu inside a service, so people stay on the task. Order chrome from GOV.UK-wide at the top to page-specific at the bottom. **Sourced opinion.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/)
- **Vercel, 26 February 2026, product changelog rather than a design essay.** The redesign’s stated reasons are consistency, hiding the sidebar when it is not needed, ordering items by common workflows, and a one-handed mobile bottom bar. **Observed product rationale.** — [Dashboard navigation redesign](https://vercel.com/changelog/dashboard-navigation-redesign-rollout)
- **GitHub, 16 July 2025, on why a power-user nav tool stayed.** Deprecation of the command palette was paused because qualitative feedback showed it was integral even where metrics undercounted it. The docs frame the palette as a way to avoid “navigating through a series of menus.” **Observed.** — [Changelog](https://github.blog/changelog/2025-07-15-upcoming-deprecation-of-github-command-palette-feature-preview/); [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette)
- **Apple HIG, pages updated through 2025–2026.** “Choose items deliberately to avoid overcrowding.” People must be able to distinguish and activate each toolbar item. “Use a tab bar to support navigation, not to provide actions.” Keep the tab bar visible while moving between sections. Sidebars: when space is limited, a tab bar may be the better navigation. **Sourced opinion.** — [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars); [Toolbars](https://developer.apple.com/design/human-interface-guidelines/navigation-bars); [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- **NN/g, Page Laubheimer, 4 April 2021 (before the window, still the article design systems echo).** Sticky headers help only when the controls are needed during the scroll. Ask what the header contains and whether those items are needed often in the session. Keep the bar small, especially on mobile; aim for readable type and about 1cm × 1cm touch targets, then cut extra height. Opaque, high contrast; no translucent bar over text. Motion should be minimal. A partially persistent header (hides while scrolling down, returns on scroll up) is a compromise, not a default. If the bar is not doing a job, do not stick it. **Sourced opinion.** — [Sticky Headers](https://www.nngroup.com/articles/sticky-headers/)
- **GitLab Pajamas, 15 July 2026.** Sidebar navigation is contextual. A minimal layout removes navigation when it does not help. Hiding the sidebar is a user preference so the body can have focus. **Sourced opinion.** — [Navigation sidebar](https://design.gitlab.com/patterns/navigation-sidebar)
- **Stripe Apps docs, undated page fetched via search.** The header gets the name, the view, one external link, and a few actions. Consistency and contrast outrank custom chrome. No essay by a named Stripe designer on marketing-site or docs-site navigation simplicity was found in this pass. **Sourced opinion, narrow scope.** — [Design your app](https://docs.stripe.com/stripe-apps/design)
- **Khan Academy, 2025–2026 public design writing is about color and brand, not nav structure.** Caitlyn Mayers, 23 March 2026, describes the reimagined UI’s color system and a 4.5:1 text contrast bar. The June 2026 admin article lists “Site navigation: Improved” with no further claim. **Observed absence of a nav essay; the color post is real.** — [Color system](https://blog.khanacademy.org/how-we-rebuilt-khan-academys-color-system-from-the-ground-up/); [Reimagined experience](https://support.khanacademy.org/hc/en-us/articles/46056304557837-What-do-administrators-need-to-know-about-the-Khan-Academy-reimagined-experience)
- **Duolingo’s public structural statement is the path, and an older illustration rule about not adding detail.** The 2022 home-screen post: one guided path, topic names on the unit header and in a popup, a bottom-corner jump-back because the scroll is long. Brand illustration guidelines (shape-language page, fetched as a 2025 page) say to use the fewest shapes that stay readable on a small screen, because unclear visuals make learners fail the task. That sentence is about drawings, not the header. **Sourced opinion.** — [Home screen redesign](https://blog.duolingo.com/new-duolingo-home-screen-design/); [Shape language](https://design.duolingo.com/illustration/shape-language)
- **web.dev, 2022, Manuel Matuzović, still a useful implementation constraint.** He writes that he is not a fan of hiding the main navigation on narrow viewports, but a long list forces it. Hide the list, not the `<nav>` landmark, and expose a button that is actually named. **Sourced opinion, just outside the year window.** — [Building the main navigation for a website](https://web.dev/articles/website-navigation)

### Inferences

- “Navigation simplicity” in these primary sources means fewer jobs in the top bar and a shorter list of top-level links, not the deletion of search or of the section outline. Primer and GOV.UK both describe a calm page whose local navigation carries the hierarchy the header refuses to repeat.
- Vercel and GitLab are the 2026 sources that treat hide/show of the section nav as a product feature. Apple treats hiding of the top-level section switcher as a bug. A reading product can follow the first rule for the track sidebar and the second rule for a very small set of site sections, but that distinction is an inference, not a sentence any of them wrote about education.

### Gaps

- No 2023–2026 talk, blog post, or design-system chapter was found in which a named Stripe, Khan Academy, or Duolingo designer discusses header simplicity, announcement bars, or lesson chrome.
- Primer’s responsive-API ADR linked from the layout page is internal (“currently only available for hubbers”) and was not read.
- The Apple toolbars URL returned only a title in direct fetch. Quotes above rely on the indexed HIG text from search. If a quotation mark matters to the final report, re-open [the navigation-bars HIG](https://developer.apple.com/design/human-interface-guidelines/navigation-bars) in a browser.

## For an education library, is the header a catalog, a wayfinding tool, or a reading tool?

### Takeaway

The sources do not pick one job for every page. They separate pages. Home and start pages orient and list top-level choices. A long task or article keeps the outline beside the text, or one screen earlier, and uses the top bar to say where you are and how to search or leave. Putting the catalog, the wayfinding, and the reading controls in the same header is the pattern these systems keep cutting.

### Cited Findings

- **Start page versus in-task page, GOV.UK.** The topic menu is for the homepage and mainstream guidance, where the job is to explore. After the start page, the service should contain what the user needs; extra information is linked from the page body. Service navigation, when it exists, is a short list of top-level sections plus service tools such as in-service search, not a catalog of every page. A linear journey should not have that list at all. Page-specific elements, including breadcrumbs, come after the service header, immediately before main content. **Sourced opinion.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/)
- **GitHub’s own page anatomy splits the same way.** The app header carries global navigation, actions, a short context region, and local navigation, and it scrolls away. It may include notification banners. The left pane is where navigation and filtering live, with independent scroll on split pages. The page header region (title, actions, summary, local navigation) is not the app header. The content region is the subject of the page. Full pages cap width so lines do not get too long (`xlarge`, 1280px, including padding). **Sourced opinion.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/)
- **Docs homes and docs articles already use different densities, even when they share a header.** Next.js’s docs home is a short orientation page (“What is Next.js?”, three sections, a pointer to courses) and still shows search, Ask AI, theme, sidebar, and “On this page”. The sidebar, not the header, is what the page tells you to use to move through sections. Stripe’s docs home, in the markdown extract, is a catalog of products and use cases with no lesson chrome in the extract. roadmap.sh’s frontend URL is a catalog: path title, Projects and AI Tutor tabs, a personalize control, and a long explainer, with `⌘ K` and a partner banner. **Observed.** — [Next.js docs](https://nextjs.org/docs); [Stripe docs](https://docs.stripe.com); [roadmap.sh frontend](https://roadmap.sh/frontend)
- **MDN attaches the section catalog to the article, not to a global map in the header.** Sidebars are per document tree, data-driven, and can be localized. A sidebar section title commonly links to that area’s landing page. The learn-module page that was fetched is itself a catalog of tutorials inside the article body. **Sourced opinion plus a partial page observation.** — [MDN sidebars](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Page_structures/Sidebars); [Your first website](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website)
- **Duolingo’s home is the catalog (the path). The lesson is a different surface.** The 2022 article describes the home screen as the ordered path. Tapping a node opens a popup with the topic; the lesson content itself is not the home header. Labels were removed from the circles and placed on unit headers so the path could stay a path. **Sourced opinion.** — [New Duolingo home screen](https://blog.duolingo.com/new-duolingo-home-screen-design/)
- **Khan Academy’s public home is a course catalog.** The fetched home is organized as “Explore our courses,” with signup for teachers and a claim about self-paced progress. The 2026 reimagined notes add a student learning queue and say navigation and search improved. The lesson-page choice (catalog versus reading chrome) was not visible in these sources. **Observed home; lesson page missing.** — [Khan Academy](https://www.khanacademy.org/); [Reimagined experience](https://support.khanacademy.org/hc/en-us/articles/46056304557837-What-do-administrators-need-to-know-about-the-Khan-Academy-reimagined-experience)
- **Apple’s split is the clearest “three tools” model, and it is not a website header.** Top toolbar: current title, back/forward, search, and a few actions. Tab bar: switch top-level areas, and do not hide it. A toolbar on the current view is for actions on that view. Sidebars carry more destinations when the window is wide, and can adapt to a tab bar when it is not. **Sourced opinion.** — [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars); [Toolbars](https://developer.apple.com/design/human-interface-guidelines/navigation-bars); [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)
- **Guided sequences that put the whole journey in a header have already failed a research note.** GOV.UK step-by-step content lives in a sidebar or on a dedicated page. The header variant of that pattern is rarely used, and the design system says the purpose may be unclear. **Sourced opinion.** — [Step by step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/)

### Inferences

- On a lesson page, the sources that describe reading behavior (Primer’s focus rule, NN/g’s content-to-chrome rule, GitLab’s hideable contextual sidebar, Next.js’s sidebar plus “on this page”) treat the header as wayfinding and identity. The catalog of the track is the sidebar or the previous page. Reading tools that refer to this document (in-page contents, collapse sidebar, skip to content) sit with the article, not in a second global menu.
- On a home or path page, the same organizations use the page body as the catalog (Khan course explore, roadmap.sh path, Duolingo path, Stripe docs product index, GOV.UK homepage menu). The header stays a short wayfinding bar so the catalog can be the page.
- A single header that is catalog plus wayfinding plus reading progress would contradict GOV.UK’s “not a site map,” Primer’s “not a full-path breadcrumb,” and Primer’s ban on stacking a long link list above the content. That contradiction is the inference; none of those pages mention an education library.

### Gaps

- No before/after of one education product’s lesson header versus its homepage was captured. Odin’s lesson page did not render. Khan and Duolingo lesson views were not opened.
- “On this page” versus prev/next at the bottom of the article was visible as a docs habit on Next.js only in part: the page has “On this page” and ends with a getting-started link, not a measured prev/next component. Starlight and Docusaurus pagination were not opened.

## Concrete failures: hidden next steps, 320px overflow, focus traps, search that misses the header

### Takeaway

The failures that are specified in accessibility standards and design systems are: a sticky header that covers the focused or targeted control, a bar so tall or so crowded that a 320px-wide screen cannot show the content or the targets, a menu that traps keyboard focus without behaving as a real modal, and a section outline pushed above the lesson so the next lesson is a scroll away. A named case of site search missing the same sections the header links to was not found.

### Cited Findings

- **A sticky header hides the next control for keyboard and anchor users.** WCAG 2.2 success criterion 2.4.11 Focus Not Obscured (Minimum), level AA: when a component receives keyboard focus, author-created content must not hide it completely. Sticky headers, sticky footers, cookie banners, and chat widgets are the usual authors of that content. Partial cover passes AA; full cover fails. AAA 2.4.12 is stricter. Practical write-ups from 2022 through 2026 name the same bug: Shift+Tab scrolls the link to the top of the viewport and the sticky header covers it; in-page anchors land under the bar. The repair these sources agree on is `scroll-padding-top` (or `scroll-margin`) equal to the sticky height, not a second copy of the link. **Sourced opinion, normative plus implementation notes.** — [TPGi, December 2022, updated March 2023](https://www.tpgi.com/prevent-focused-elements-from-being-obscured-by-sticky-headers/); [AAArdvark, 18 August 2026](https://aaardvarkaccessibility.com/your-focus-ring-is-fine-your-sticky-header-ate-it/); [EqualWeb summary of 2.4.11](https://www.equalweb.com/wcag/criteria/2-4-11/)
- **NN/g’s content-to-chrome failure is the same bug in reading terms.** A sticky header that is also a large logo, plus a second sticky bar, left their example site at roughly a 2:1 content-to-chrome ratio on an iPhone 11 Pro. They contrast that with a much smaller header at about 13:1. Translucent sticky bars fail contrast against whatever content they cover. **Sourced opinion.** — [Sticky Headers](https://www.nngroup.com/articles/sticky-headers/)
- **The next lesson is hidden when the track list is stacked above the article.** Primer’s explicit failure: a sidebar of many links placed above the content on a narrow viewport forces the reader to scroll before they can read. GOV.UK’s step-by-step header is a researched version of “the next step is in the chrome and people do not use it.” **Sourced opinion.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/); [Step by step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/)
- **320px is a named layout width, and overflow is a loss-of-function bug, but no education site was measured at 320px here.** Primer sets an `xsmall` breakpoint at 320px and a narrow range under 768px that must be a single column. “Pages should adapt to smaller screens, without loss of functionality.” Interstitial pages (sign-in and similar) are often capped at that 320px width. Horizontal padding at `xsmall` is 16px, so the content column inside a 320px viewport is about 288px before any scrollbar. Apple’s layout guidance: respect the safe area so toolbars and the status bar do not cover controls; do not change functionality when space changes, only how much is visible. **Sourced opinion. Not an instrumented audit of a live education header.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/); [Apple layout](https://developer.apple.com/design/human-interface-guidelines/layout)
- **Icon buttons in a crowded header fail the 24px target rule even when the icon looks fine.** WCAG 2.2 criterion 2.5.8 Target Size (Minimum), level AA, understanding document updated 3 September 2026: pointer targets are at least 24 by 24 CSS pixels, unless spacing, an equivalent larger control, inline text, user-agent rendering, or an essential presentation applies. The understanding doc recommends meeting the size even when spacing would excuse it, and points important controls at the older 44px AAA criterion. W3C’s “in brief”: some people cannot hit small buttons that sit close together. NN/g’s 2021 mobile guidance is stricter in practice: about 1cm × 1cm. Theme icons, social icons, and unlabeled icon buttons are the controls these criteria hit. **Sourced opinion.** — [Understanding 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html); [Sticky Headers](https://www.nngroup.com/articles/sticky-headers/)
- **A menu that traps Tab is a modal dialog, and using that behavior on ordinary navigation is the failure.** W3C’s modal dialog pattern: Tab and Shift+Tab cycle inside the dialog and do not leave; Escape closes; focus moves in on open and returns to the invoker on close; `aria-modal="true"` is allowed only when pointer users also cannot use the page behind and the dimming matches. Marking a dialog modal when it is not modal “will experience severe negative ramifications” for some assistive technologies. The disclosure pattern, which W3C uses for show/hide navigation panels, does not trap Tab: Enter or Space toggles, and Tab is free to move on. A hamburger that traps focus, offers no Escape, or does not restore focus is a broken dialog, not an acceptable menu. **Sourced opinion.** — [Dialog (Modal) pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/); [Disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)
- **web.dev’s implementation note is the non-trap version.** On a narrow viewport, a button shows and hides the link list; the `<nav>` landmark stays in the page. The article is from 2022 and does not itself document a broken education menu. **Sourced opinion.** — [Building the main navigation](https://web.dev/articles/website-navigation)
- **Search and the header are supposed to cover the same service, not two different maps.** GOV.UK: a search field in Service navigation searches that service only, and the placeholder should say so (“Search [your service]”). GitHub’s command palette is scoped to the current location and, if the desired page is not in the first suggestions, the user types the name or path; the docs present this as the way to reach pages that exist in the product. Stripe Dashboard search is how users move across object types without hunting the navigation. NN/g’s sticky-header article points to an older companion piece, “Search Is Not Enough: Synergy Between Navigation and Search,” as related reading; that article was not re-read in this pass, so its claims are not repeated here. **Sourced opinion. No incident report.** — [Navigate a service](https://design-system.service.gov.uk/patterns/navigate-a-service/); [GitHub Command Palette](https://docs.github.com/en/get-started/accessibility/github-command-palette); [Stripe Dashboard search](https://docs.stripe.com/dashboard/search)
- **GitHub Primer’s header is specified as not sticky, which avoids the focus-obscured class of bugs on github.com’s app chrome.** “App header is never fixed to the top of the viewport.” Primer’s separate brand subdomain nav can be fixed; that is a different component, and its accessibility notes require a skip link as the first control and a target that clears the fixed bar. **Sourced opinion.** — [Primer layout](https://primer.style/product/getting-started/foundations/layout/); [Subdomain nav bar](https://primer.style/brand/components/SubdomainNavBar/)

### Inferences

- “Header hides the next lesson” is not a metaphor in these sources. It is either a sticky bar covering the next link (2.4.11 and anchor jumps) or a track menu that consumes the first screens on a phone (Primer). Both are specified. A third version, Duolingo removing labels from path nodes, was a deliberate trade for a popup and a unit header, and the company published the recovery path. That is not the same defect.
- A 320px overflow was not photographed. The specified failure is any header whose items do not reflow or collapse inside Primer’s 320px `xsmall` width and Apple’s safe area, especially once a 16px side inset, a logo, a menu button, search, theme, and an account icon are all in one row. That list of controls is an inference from the components observed on Next.js and Tailwind, not a measured overflow.
- Search that cannot find a section the header links to would violate the GOV.UK and GitHub assumption that in-product search and navigation are two indexes of one service. No public bug of that form was collected, so it stays a specified risk rather than a case study.

### Gaps

- No keyboard audit was run. No focus trap was reproduced on MDN, Next.js, Khan Academy, roadmap.sh, or GitHub Docs. The failure is the W3C mismatch (disclosure versus modal), not a ticket against one of those sites.
- No 320px screenshot or CSS measurement of an education header was taken. Primer’s 320px breakpoint is the evidence that this width is a design target, not proof that a particular site overflows it.
- No bug report was found of a docs or course search index missing pages that the header itself links to.
- Cookie banners, which 2.4.11 write-ups treat as equal offenders with sticky headers, were not inventoried on the education sites.
