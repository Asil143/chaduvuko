# Product-company careers pages (Stripe, Notion, Linear, Vercel, Anthropic)

Observed 13 October 2026 by fetching the public pages below. Salary amounts are not copied. Where a page shows a number, the notes say only that a range is present.

## For each company, what are the public jobs-index URL and one real job-detail URL?

### Takeaway
Stripe and Anthropic split a long brand careers page from a separate jobs index, and Anthropic’s job detail leaves the site for Greenhouse. Notion and Linear put the role list on the same URL as the brand essay; Notion’s detail is Ashby-hosted, while Linear renders the description on linear.app and embeds Ashby for the form. Vercel’s index and detail are both on vercel.com, with Greenhouse as the posting source.

### Cited Findings
- Stripe’s suggested URL `https://stripe.com/jobs` is a brand page, not a list. Its visible H1 is “Implement the conditions for prosperity.” The jobs module is a card labeled “Open roles” linking to `/careers/search` (“We’re hiring. Explore our open roles and submit your application.”). — [Stripe jobs](https://stripe.com/jobs)
- Stripe’s public index is `https://stripe.com/careers/search`. One live detail URL from that list is `https://stripe.com/careers/listing/ai-engineer/8144196` (title “AI Engineer”; page data `postedAt` 2026-10-07; `greenhouseId` 8144196). The same title is repeated on the index once per office, including Toronto, Atlanta, and Chicago, all pointing at that listing. — [Stripe open roles](https://stripe.com/careers/search); [Stripe AI Engineer listing](https://stripe.com/careers/listing/ai-engineer/8144196)
- Notion’s jobs index that returned content is `https://www.notion.com/careers`. Open roles are links to `https://jobs.ashbyhq.com/notion/{uuid}`. The detail opened is `https://jobs.ashbyhq.com/notion/def3f337-5593-491c-b34d-e0b53f2a5cac`, titled “Software Engineer, AI Product Security,” department and team “Engineering,” primary location “San Francisco, California,” employment type FullTime. The index row for that role also prints “New York, New York” beside San Francisco. Ashby’s public posting API (`https://api.ashbyhq.com/posting-api/job-board/notion`) returned this job’s `jobUrl` as that same Ashby URL. — [Notion careers](https://www.notion.com/careers); [Ashby posting API](https://api.ashbyhq.com/posting-api/job-board/notion)
- A markdown fetch of the Ashby job URL returned only the document title “Software Engineer, AI Product Security @ Notion.” The description headings below come from `descriptionHtml` on the posting API for that id, not from a rendered screenshot. — [Notion Ashby job](https://jobs.ashbyhq.com/notion/def3f337-5593-491c-b34d-e0b53f2a5cac); [Ashby posting API](https://api.ashbyhq.com/posting-api/job-board/notion)
- Linear’s index and brand page are the same URL, `https://linear.app/careers`. One detail URL is `https://linear.app/careers/0c7c2e26-0a98-42cf-a47c-9a3999fb513b` (“Product Engineer,” under Engineering, location “North America”). - Vercel’s index is `https://vercel.com/careers`. One detail URL is `https://vercel.com/careers/software-engineer-backend-us-5430088004` (“Software Engineer, Backend”). The detail page’s embedded position data includes `absolute_url` on `https://job-boards.greenhouse.io/vercel/jobs/{id}`. The candidate-facing page fetched is the Vercel URL, not the Greenhouse board. — [Vercel careers](https://vercel.com/careers); [Vercel Software Engineer, Backend](https://vercel.com/careers/software-engineer-backend-us-5430088004)
- Anthropic’s brand page is `https://www.anthropic.com/careers`. It does not list jobs. It links “Explore open roles” to `/careers/jobs`. The index is `https://www.anthropic.com/careers/jobs`. Rows link “Apply” to `https://job-boards.greenhouse.io/anthropic/jobs/{id}`. The detail opened is `https://job-boards.greenhouse.io/anthropic/jobs/5026097008`, “Staff Software Engineer, Product,” under the index group “Engineering & Design - Product,” locations “San Francisco, CA | New York City, NY | Seattle, WA.” — [Anthropic careers](https://www.anthropic.com/careers); [Anthropic jobs](https://www.anthropic.com/careers/jobs); [Greenhouse posting](https://job-boards.greenhouse.io/anthropic/jobs/5026097008)
- ATS, from page source or the host that serves the posting: Stripe listing JSON includes `greenhouseId` and the HTML mentions Greenhouse, but the public listing is on stripe.com. Notion careers HTML references Ashby, and every sampled role link is `jobs.ashbyhq.com`. Linear careers and the Product Engineer page reference Ashby; the form container is `id="ashby_embed"`. Vercel careers and the backend-engineer page reference Greenhouse and a `job-boards.greenhouse.io/vercel` absolute URL. Anthropic’s index links the Greenhouse board directly (`job-boards.greenhouse.io/anthropic`). — [Stripe listing](https://stripe.com/careers/listing/ai-engineer/8144196); [Notion careers](https://www.notion.com/careers); [Linear job](https://linear.app/careers/0c7c2e26-0a98-42cf-a47c-9a3999fb513b); [Vercel job](https://vercel.com/careers/software-engineer-backend-us-5430088004); [Anthropic jobs](https://www.anthropic.com/careers/jobs)

### Inferences
- “Careers” and “jobs index” are different URLs at Stripe and Anthropic. Treating `stripe.com/jobs` or `anthropic.com/careers` as the index would describe the essay, not the list.
- UUID job paths on Notion and Linear match Ashby. Numeric ids on Stripe, Vercel, and Anthropic match Greenhouse. The candidate still sees a first-party page at Stripe, Linear, and Vercel; only Notion and Anthropic send the detail click straight to the ATS host.

### Gaps
- `notion.so/careers` was not fetched. The index recorded here is `www.notion.com/careers`.
- The Ashby job page did not render its chrome to the markdown fetcher, so Apply placement on that host is not from the live DOM. Headings are from the posting API HTML for the same id.
- The Greenhouse board URL inside Vercel’s page data was not opened. Section headings for Vercel are from the vercel.com job page.
- No screenshot was taken, so nothing here is a visual measurement of columns, type size, or density.

## What sits above the jobs list, how is one row built, and what is absent?

### Takeaway
The list itself is a dense row of title plus location, sometimes team, with a text link or the whole row as the link. Stripe and Anthropic keep that list free of the company essay. Notion and Linear put a long essay, values, and (Notion) benefits on the same page above “Open Positions” or “Open roles.” Vercel’s fetched index is a short headline and a flat list.

### Cited Findings
- Stripe index, above the rows: an illustration, then H1 “Help implement the conditions for prosperity. Work on problems that matter at scale.”, a text link “Assess your fit” to `/careers/compatibility`, then the word “Search”, then “Filter by” with four controls labeled “Company”, “Teams”, “Office location”, and “Role type”, plus “0 filters selected” and “Clear all filters”. There is no multi-paragraph mission essay on this URL. — [Stripe open roles](https://stripe.com/careers/search)
- Stripe row: title as a link, then team, then one location. Example: “AEO and GEO Marketing Manager”, team “Marketing”, location “Remote in Canada”, href `/careers/listing/aeo-and-geo-marketing-manager/7844214`. The same href is repeated as separate rows for other offices. The fetched row text has no “Apply” button and no arrow character. Under the list is an equal-opportunity statement and accommodation contact `accommodations@stripe.com`, not another essay. — [Stripe open roles](https://stripe.com/careers/search)
- The Stripe essay that is absent from the index lives on `https://stripe.com/jobs`: H1 as above, “Our mission is to increase economic growth.”, sections “Speed and craft compound”, “Better defaults exist”, “Built for the best”, “We’re building the economic infrastructure for AI”, a stats strip, “Solve the problems that matter at scale”, and an FAQ (“What does it take to do well at Stripe?”, “What does career growth look like at Stripe?”, “What should I expect during the Stripe hiring process?”, “How do I know if a Stripe recruiter contacting me is legitimate?”). — [Stripe jobs](https://stripe.com/jobs)
- Notion, above the list, on the same URL: a video block, H2 “Our values” with four named items (“Customer in every room”, “Own the outcome”, “Why not today”, “Direct and kind”), H2 “Life at Notion” with a paragraph on in-person days and city blocks (San Francisco, New York, Dublin, Seoul, Hyderabad, Tokyo, Sydney) plus a quote from Andrew McCarthy, H2 “Benefits” with “Health & Wellbeing”, “Everyday Life”, “Family Support”, “Financial Future”, “Time Away”, and “Learning & Growth”, then H2 “Open Positions”. — [Notion careers](https://www.notion.com/careers)
- Notion list chrome: “Filter by”, a location list beginning “All locations” (Amsterdam through Tokyo) with “Clear location”, a department list beginning “All departments” (Early Career through User Research and Product Operations) with “Clear department”, and “Skip to end”. ### Inferences
- Two index shapes are both in use. Stripe and Anthropic: short or empty intro, filters, then rows, with the essay on a parent URL. Notion and Linear: the essay is the page, and the list is a section near the bottom. Vercel’s fetched index is closer to the first shape but without a visible filter bar.
- Row anatomy is stable: title is the primary text, location is secondary, team is either a row field (Stripe), a group heading (Notion, Linear, Anthropic), or omitted (Vercel’s flat list). The row action is a quiet link (“Learn more”, the row itself) except Anthropic, which prints “Apply” on the index and sends the click to Greenhouse.
- None of the five indexes uses the job row to hold responsibilities, a long “about” blurb, or an interview outline.

### Gaps
- Vercel’s HTML contains the strings “Filter”, “Department”, “Location”, and “Search” many times, including inside job JSON. The markdown rendering of the page did not show filter controls. A client-only filter that never appears as text cannot be ruled out.
- Anthropic filter option labels were not extracted, only the words Team, Role, and Location plus the presence of select and input elements.
- Stripe and Vercel index arrows were not confirmed. Detail-page buttons on Stripe use an `hds-icon-hover-arrow` class; that was not found on an index row.
- No page stated a font size or a density rule. Tailwind and design-system class names were seen in source and are not treated as measured type size.

## On the job page, what is the heading order, where does Apply sit, and which of About / responsibilities / requirements / interview / benefits actually appear?

### Takeaway
Each job page opens with the title, location or team facts, and an Apply control, then a short sequence of about, responsibilities, and requirements. A labeled interview process is not on these five job pages. Pay is either a numeric range (Stripe, Vercel, Anthropic), the phrase “competitive” with no range in the fetched text (Linear), or absent from the posting API record (Notion). Only Stripe’s markup has an explicit sidebar of facts beside the body.

H1 is “AI Engineer”. — [Stripe AI Engineer](https://stripe.com/careers/listing/ai-engineer/8144196)

### Inferences
- The professional job page in this set is a title, a few facts (team, location, employment type), Apply within reach of the title, then three content blocks: company or team context, the work, and the bar. Interview logistics and the long benefits catalog are usually elsewhere: Stripe’s hiring FAQ on `/jobs`, Anthropic’s “How we hire” and “How we support you” on `/careers`, Notion’s benefits on the careers page above the list. Linear is the exception that puts offer bullets on the job under “What we offer” and only links out for the work-trial story.
- Sidebar versus column is not one pattern. Stripe’s HTML names a sidebar of four facts plus a sticky Apply. Linear, Vercel, and the Anthropic Greenhouse board did not. Their Apply control is a top link or button and, except Stripe, a form after the description.
- Compensation display is inconsistent even among Greenhouse-backed pages: Stripe and Anthropic and Vercel show a numeric range on the job; Linear’s fetched job says “competitive” and does not show a range; Notion’s API record for the sampled job has no compensation object.

### Gaps
- Notion Ashby chrome (whether Apply is a top button, a right column, or only a bottom form, and whether location and team are sidebar facts) was not visible because the page is client-rendered. The shell HTML was fetched and did not include the posting body.
- Stripe “Pay and benefits” was only read through the salary-range and OTE sentences. Later benefit lines, if any, were not captured.
- Anthropic `job__tags` and `job__pay-ranges` exist as classes. Tag text was not extracted. The salary sentence was read from the description body; whether `job__pay-ranges` repeats that range in the header was not separated out.
- “About Anthropic” appearing twice may be a repeated block in the Greenhouse template. It is reported as duplicated text, not as two different sections.
- No computed layout was measured. “Sidebar” for Stripe is from class names and fact labels. “Single column” for the others means those class lists had no sidebar and the fetched reading order is header, body, then form.
